# 行为评估案例

这些是人工或代理评估场景，未执行时不可标记为通过。结构和回归测试不能代替真实需求交付评估。

| 场景 | 输入 | 通过标准 |
| --- | --- | --- |
| HTML PRD | 为收藏功能输出 PRD 与原型 | 从正文骨架起草；确认章节取舍；保留核心章节、范围和共享规则；交付前运行校验 |
| 小需求裁剪 | 只修改一处提示文案 | 沿用已有文件，不强制产出全部流程图；保留已确认的章节选择 |
| 缺失安装文件 | 已有其他 .agents/workflows，但没有校验器 | 识别不完整安装，修复所需文件后读项目工作流，不仅按目录存在就跳过 |
| 调研无证据 | 评估收藏功能是否值得做，没有反馈数据 | 明确假设与证据缺口，不伪造访谈、评论、比例或样本量 |
| 双栏阅读 | 打开 PRD 并定位到一个功能 | 默认 dock 收起、iframe 延迟加载；展开后切页、缩放与滚动联动有效 |
| 编辑与恢复 | 改正文、删除表格行后撤销 | 文字与结构使用统一撤销栈；恢复后的控件可用，刷新不承诺保留撤销历史 |
| 复制含图 | 复制含原型和流程图的 PRD | iframe 转内联图片；服务失败明确提示缺图，不静默移除 |
| 交互流程图 | 多页面含回流与标签的 screen flow | 直角路径、审计通过、零遮挡；导出前检查独立与嵌入态 |
| 验收与复盘 | 从 PRD 生成验收表，再分析上线数据 | 边界从对应功能提取；数据结论有口径并区分原因假设 |
| 用户修改保留 | 已自定义工作流和 PRD 骨架后升级 | 保留自定义内容，提议更新写到 updates，不误覆盖 |
| 无浏览器 | 环境不能运行交互验证 | 如实报告未验证项，不将机械检查说成全部通过 |
